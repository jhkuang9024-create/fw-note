## Q1：结合日志分析一下播放U盘中mp4文件的详细流程

### 1) U盘识别/枚举阶段（扫描出可播放视频）

- U盘挂载点为 `/storage/22E5-D56C`，存在周期性探测/访问失败日志：`UDISK 22E5-D56C` + `falied access file 2`（[play_local_video_1.log:L105-L107](file:///Users/jhkuang/Desktop/work/%E9%9C%80%E6%B1%82(%E7%9C%81%E4%BB%BD)/%E4%B8%AD%E5%B1%8F/note/play_local_video_1.log#L105-L107)）。
- `FileUtils.isVideo` 对U盘目录做遍历识别（打印 fileName + mimeType），会扫到 `.Trashes`、各种非媒体文件，属于“媒体库/文件扫描”链路噪声（例如 [play_local_video_1.log:L913-L924](file:///Users/jhkuang/Desktop/work/%E9%9C%80%E6%B1%82(%E7%9C%81%E4%BB%BD)/%E4%B8%AD%E5%B1%8F/note/play_local_video_1.log#L913-L924)）。
- 真实文件与 macOS 资源文件 `._xxx.mp4` 都可能被识别为 `video/mp4`，会带来“列表脏数据/重复文件”风险（[play_local_video_1.log:L34072-L34075](file:///Users/jhkuang/Desktop/work/%E9%9C%80%E6%B1%82(%E7%9C%81%E4%BB%BD)/%E4%B8%AD%E5%B1%8F/note/play_local_video_1.log#L34072-L34075)）。

- `MoviePlayer` 收到 file URI 并确认 `scheme:file`（[play_local_video_1.log:L17063-L17066](file:///Users/jhkuang/Desktop/work/%E9%9C%80%E6%B1%82(%E7%9C%81%E4%BB%BD)/%E4%B8%AD%E5%B1%8F/note/play_local_video_1.log#L17063-L17066)）。

## Q2：分析一下数据流的处理流程

### 数据流总览（Data Path）

`file:///storage/...mp4` → `fd/offset/length` → `NU-GenericSource` 读文件 → `AmFFmpegExtractor` 解复用（拆为音视频轨）→ `AmAnotherPacketSource`（音频队列/视频队列）→ `Decoder`（音频FFmpeg/C2，视频硬解/tunnel）→ `Renderer` 同步输出到 AudioSink / Surface。

关键证据：

- setDataSource：`setDataSourceAsync fd 9/0/23059633`（[play_local_video_1.log:L17146](file:///Users/jhkuang/Desktop/work/%E9%9C%80%E6%B1%82(%E7%9C%81%E4%BB%BD)/%E4%B8%AD%E5%B1%8F/note/play_local_video_1.log#L17146)）
