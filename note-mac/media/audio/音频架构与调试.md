## 一、整体架构

### 1.1 架构全景图

本工程的音频栈分 **8 层**，从 APP 到功放芯片：

```
┌──────────────────────────────────────────────────────────────────┐
│ ① 应用层 (APP)                                                   │
│    AudioManager / AudioTrack        DroidAudioManager(amlogic扩展)│
├──────────────────────────────────────────────────────────────────┤
│ ② Java 框架层 (system_server 进程)                                │
│    AudioService / AudioDeviceBroker     DisplayService(输出切换)   │
├──────────────────────────────────────────────────────────────────┤
│ ③ JNI + Native 客户端 (libaudioclient)                            │
│    AudioSystem / AudioTrack.cpp → Binder                          │
├──────────────────────────────────────────────────────────────────┤
│ ④ 服务端 (audioserver 进程) ★策略核心★                            │
│    AudioFlinger(混音)   AudioPolicyService + AudioPolicyManager   │
│      ↑ amlogic定制: AmlAudioPolicyManager / libaudiopolicyengine_│
├──────────────────────────────────────────────────────────────────┤
│ ⑤ droidaudio 厂商服务 (独立进程 /system_ext/bin/hw/droidaudio)    │
│    DroidAudioConfigSetting / DroidAudioEffectSetting              │
├──────────────────────────────────────────────────────────────────┤
│ ⑥ Audio HAL (audio.primary，106 个文件)                           │
│    audio_hw.c + MS12管线 + aml_audio_output + alsa_manager        │
├──────────────────────────────────────────────────────────────────┤
│ ⑦ 内核 ALSA 驱动 (common/common14-5.15/common/common_drivers)     │
│    AUGE 音频子系统 + codec/功放驱动                                 │
├──────────────────────────────────────────────────────────────────┤
│ ⑧ 硬件: codec / DAC / 功放(i2c) / HDMI-TX / SPDIF / USB          │
└──────────────────────────────────────────────────────────────────┘
```

### 1.2 关键进程与职责

| 进程/服务 | 职责 | 关键点 |
|---|---|---|
| APP | 使用 AudioManager/AudioTrack 播放、控制 | 厂商扩展走 DroidAudioManager |
| system_server | AudioService（音量/焦点）、DisplayService（输出切换） | 音频相关决策多转发给 audioserver |
| audioserver | AudioFlinger（混音）+ AudioPolicyService（路由策略） | **实际控制音频走向的进程** |
| droidaudio | TV 特有控制：透传、demux、混音、音效、Karaoke | 独立 AIDL 服务，不占 audioserver |
| audio HAL | 对接 ALSA：通路切换、格式处理、MS12 解码 | 106 个文件的巨型 HAL |
| kernel | AUGE 硬件通路、codec/功放寄存器控制 | 在 common_drivers 目录 |

### 1.3 三条关键数据流

```
① 播放流：   APP(AudioTrack) → AudioFlinger Track → MixerThread 混音
             → HAL out_write → alsa pcm 写 → codec/DAC → 功放/HDMI

② 路由流：   AudioService/AudioPolicyService → APM(engine 决策)
             → setOutputDevices/installPatch → AudioFlinger → HAL → 通路切换

③ 控制流：   APP → DroidAudioManager(Java) → droidaudio(AIDL)
             → DroidAudioConfigSetting → AudioSystem::setXxx / 属性
             → APM / HAL（setParameters 字符串通道）
```

### 1.4 本工程定制的 5 大特点（理解代码的钥匙）

1. **三态输出策略**：`persist.vendor.media.audio.output.strategy` = AUTO(0)/SEMI_AUTO(1)/MANUAL(2)
2. **双引擎机制**：`libaudiopolicyengine_amlogic` 只在半自动模式加载（见 [AmlAudioPolicyManager.cpp:89-108](vendor/amlogic/common/frameworks/native/libaudiopolicymanagercustom/AmlAudioPolicyManager.cpp#L89-L108)）
3. **droidaudio 独立服务**：TV 特有音频控制从 framework 剥离成 AIDL 服务
4. **Dolby MS12 深度集成**：HAL 内 ms12 渲染/透传双管线 + 预编译 EQ/DRC 库
5. **HDMI 场景硬件静音协同**：system_server 属性 + init + i2c 功放寄存器三层联动

## 三、实际修改（改哪里、怎么改）

### 场景 1：修改"声音输出设备切换"逻辑（最常用）

调用链：`APP → DisplayManager → DisplayService → droidaudio → APM → HAL`

要改的层次对应的文件：

| 要改的行为 | 改哪个文件 |
|---|---|
| APP 侧接口（返回值/设备编号映射） | `frameworks/base/core/java/android/os/display/DisplayManager.java`（getCurAudioDevice/setCurAudioDevice + droidDevToCurDev/curDevToDroidDev） |
| Binder 接口增加方法 | `frameworks/base/core/java/android/os/display/IDisplayService.aidl` |
| 系统服务端逻辑（静音联动等） | `frameworks/base/services/core/java/com/android/server/DisplayService.java:3528` |
| 实际输出策略/设备选择 | `vendor/amlogic/common/interfaces/droidaudio/default/DroidAudioConfigSetting.cpp:930`（setOutputDevices） |
| 路由策略定制 | `vendor/amlogic/common/frameworks/native/libaudiopolicymanagercustom/AmlAudioPolicyManager.cpp` |
| 设备选择优先级 | `vendor/amlogic/common/frameworks/native/libaudiopolicyengine_amlogic/src/Engine.cpp:424` |
| 硬件静音联动 | `device/amlogic/common/products/mbox/init.amlogic.system.rc:160` |

> ⚠️ 改完 AIDL/接口后，必须 `rm -rf out/soong/.intermediates` 中相关生成文件（或干净编译），否则 Binder 接口对不上，出现空指针/TransactionTooLarge。

### 场景 2：新增一个"APP 可调的音频控制项"

完整链路需要改 5 处（以"新增卡拉 OK 模式开关"为例）：

1. **AIDL 接口**：`IDroidAudio.aidl` 加方法 → `DroidAudio.cpp` 转发 → `DroidAudioConfigSetting.cpp` 实现（调 `AudioSystem::setParameters("karaoke_enable=1")`）
2. **Java 客户端**：`vendor/.../app/DroidAudioManager.java` 加公开方法
3. **HAL 处理**：`audio_hw.c` 的 `setParameters` 解析新 key，做实际动作
4. **（可选）内核**：如需寄存器操作，在对应 codec/平台驱动加 sysfs/mixer 接口
5. **（可选）属性持久化**：persist 属性保存用户选择

> 原则：**跨进程通信只走 AIDL/Binder；framework 到 HAL 走 setParameters 字符串通道；HAL 到内核走 ALSA/mixer/sysfs。** 各层别越级。

### 场景 3：修改默认输出设备 / 开机恢复逻辑

- 用户选择持久化在两个属性：`persist.vendor.media.audio.output.strategy`（0自动/1半自动/2手动）、`persist.vendor.media.audio.forceuse`（强制设备）
- 开机时 APM 加载读 strategy 决定引擎（[AmlAudioPolicyManager.cpp:91](vendor/amlogic/common/frameworks/native/libaudiopolicymanagercustom/AmlAudioPolicyManager.cpp#L91)）；音频参数读取处见 [DroidAudioConfigSetting.cpp:958](vendor/amlogic/common/interfaces/droidaudio/default/DroidAudioConfigSetting.cpp#L958) 的 getOutputDevices
- 改默认值：找 `product` 分区属性文件（`device/amlogic/common/products/mbox/` 的 product.prop 等）或直接改 `DroidAudioConfigSetting.cpp` 的默认值

### 场景 4：改音量（曲线/步进/最大最小）

- Java 侧：`AudioService.java` 音量流定义、`AudioSystem.cpp` 索引换算
- amlogic 音量曲线：`AmlAudioPolicyManager::checkAndSetVolume`（[AmlAudioPolicyManager.cpp:313](vendor/amlogic/common/frameworks/native/libaudiopolicymanagercustom/AmlAudioPolicyManager.cpp#L313) 附近重写的音量相关方法）
- HAL 侧：`aml_volume_utils`（audio_hw.c 引用）、MS12 音量 `audio_hw_ms12_v2.c`

### 场景 5：透传模式（HDMI/SPDIF RAW 输出）

- Java：`DroidAudioManager.setHDMIPassThrough/setSPDFPassThrough`
- 服务端：`DroidAudioConfigSetting.cpp` 中透传相关实现（写 strategy/format 属性 + setParameters）
- HAL：`audio_hw_ms12_v2.c` 的 passthrough 分支、`aml_audio_spdifout.c`（SPDIF 发包）、内核 `iec_info.c`
- 注意：透传受 `AudioPolicyManager` 的 format 策略（`setSurroundFormatEnabled`，[AmlAudioPolicyManager.h:48](vendor/amlogic/common/frameworks/native/libaudiopolicymanagercustom/AmlAudioPolicyManager.h#L48)）约束

## 五、实际切换声音输出的场景分析

> 统一前提：用户通过"设置→声音输出"选择设备，APP 调 `DisplayManager.setCurAudioDevice(String)`。

### 场景 A：切到 HDMI 输出（device="1"）

```
DisplayManager.setCurAudioDevice("1")
  → curDevToDroidDev: "1" → 9 (AUDIO_POLICY_FORCE_DIGITAL_DOCK)
  → DisplayService.setCurAudioDevice(9)
      → droidaudio: 写 strategy=2(手动), forceuse=9
      → AudioSystem::setForceUse(FORCE_FOR_MEDIA, 9)
          → AmlAudioPolicyManager::setForceUse: 校验 forceuse==9 ✓
          → 基类: engine 记录 forceuse=9
          → updateCallAndOutputRouting:
              engine 对 STRATEGY_MEDIA 选设备:
                优先"最近插入的可移除设备"(BT/USB/耳机) → 为空
                → forceuse 分支: DIGITAL_DOCK → HDMI/ARC/eARC
              → setOutputDevices → installPatch → AudioFlinger → HAL → HDMI 通路
      → DisplayService: HDMI 已插入 且 输出=HDMI → sys.speaker.mute=0（功放开）
  结果: 声音从 HDMI 出；若 HDMI 没插，engine 选不到设备 → 回退默认设备
```

**关键日志**：
```
DroidAudioConfigSetting: setForceUse:9
AmlAudioPolicyManager: userDbForceUse:DIGITAL_DOCK(9) force_device:DIGITAL_DOCK(9)
Engine(或默认引擎): ... device HDMI
```

### 场景 B：切回音箱（device="0"）

与 A 对称，`forceuse=1 (SPEAKER)`，engine 选 `AUDIO_DEVICE_OUT_SPEAKER`。差异点：

- 若 HDMI 仍插着 → `sys.speaker.mute=0`（功放恢复出声）
- 若 HDMI 没插 → 无静音联动，直接切

**注意**：从 HDMI 切回音箱时 HAL 要做通路切换（HDMI 流关闭、TDM 流开启），可能有几十 ms 延迟和爆音防护（`checkDeviceMuteStrategies`）。

### 场景 C：HDMI 插着，切到非 HDMI（如音箱/蓝牙）——静音联动

```
DisplayService.setCurAudioDevice(非HDMI)
  → isHDMIPlugged()==true 且 设备!=HDMI
  → sys.speaker.mute=1
  → init 捕获属性变化 → 写 i2c 5-000e mute 寄存器 1 → 功放硬件静音
目的: 防止 HDMI 电视和外置音箱同时出声
```

**验证方法**：`getprop sys.speaker.mute` + `cat .../5-000e/mute`；或者直接听声（HDMI 有声、音箱无声）。

### 场景 D：蓝牙耳机（device="3"）

```
forceuse=4 (BT_A2DP) → engine 选 BLUETOOTH_A2DP 系列设备
前提: 蓝牙已配对连接（AudioDeviceBroker 已 setDeviceConnectionState 注册 A2DP 设备）
如果蓝牙没连 → engine 选不到 A2DP → 回退默认（音箱）
特别: 蓝牙音量走 AVRCP/独立曲线；AmlAudioPolicyManager 的防篡改校验保证
      AudioService 蓝牙事件不会覆盖用户选择
```

### 场景 E：重启后恢复

```
开机 → APM 初始化 → Aml_loadApmEngineLibraryAndCreateEngine 读 strategy:
  strategy=2(手动) → 加载默认引擎，forceuse=9 → 开机即走 HDMI 强制路由
  strategy=0(自动) → 加载默认引擎，按实际连接设备自动选
  strategy=1(半自动) → 加载 _amlogic 引擎（有 FM 等特殊逻辑）
→ HAL 初始化读属性 → 恢复用户输出
```

**用户选择不丢失的保证**：persist 属性存 `/data`，factory reset 后重置。

### 各场景排查速查表

| 现象 | 第一排查点 | 第二排查点 |
|---|---|---|
| 切到 HDMI 无声 | getprop strategy/forceuse | dumpsys audio 看路由设备 |
| 切换后爆音 | checkDeviceMuteStrategies 日志 | HAL 通路切换时序 |
| HDMI+音箱同时响 | sys.speaker.mute 值 | i2c 功放寄存器 |
| 蓝牙切不上 | 蓝牙是否连接 | engine 设备选择日志 |
| 重启后没恢复 | persist 属性是否在 | APM 启动加载日志 |

## 六、常见问题

### Q1：切换设备后完全没有声音

排查顺序：
1. `getprop persist.vendor.media.audio.forceuse` / `output.strategy` — 确认用户选择已下发
2. `dumpsys media.audio_policy | grep -i force` — 确认 APM 接受了（若显示 NONE 且属性非 0，查 AmlAudioPolicyManager 防篡改校验是否被绕过）
3. `dumpsys audio` 看当前路由设备是否为期望设备
4. `tinypcminfo -D <card>` / `tinymix` — 确认 HAL 通路状态
5. `dmesg | grep -iE "codec|sound"` — 内核 codec 是否正常
6. 功放：`cat .../5-000e/mute` — 是否被静音（HDMI 插入场景）

### Q2：切换时有爆音/pop 音

- 框架层已做 `checkDeviceMuteStrategies`（切换前静音 + 延迟恢复），爆音多发生在 HAL 层通路切换瞬间
- 检查 `audio_hw.c` 中通路切换的 mute/unmute 时序；HDMI 切换注意 `toggleHdmiDevice`（[AmlAudioPolicyManager.cpp:74](vendor/amlogic/common/frameworks/native/libaudiopolicymanagercustom/AmlAudioPolicyManager.cpp#L74)）触发的重连
- 临时规避：切换前 HAL `setParameters("mute=1")`，切换完成后解除

### Q3：HDMI 和音箱同时出声 / 想关掉音箱

- 检查 `sys.speaker.mute` 是否为 0（HDMI 插入 + 输出≠HDMI 时应为 1）
- 若属性正确仍出声：i2c 功放芯片寄存器被 codec 驱动覆盖（kernel 侧通路开启时重新 unmute）
- 修改入口：`DisplayService.java:3538-3542` 的静音逻辑；或 HAL 通路层面只开一路

### Q4：切换设置不生效（明明选了 HDMI 却从音箱出）

- `dumpsys media.audio_policy` 看 forceuse：若仍为 NONE，说明 `AmlAudioPolicyManager::setForceUse` 的校验失败——入参 ≠ persist 属性值。常见原因：APP 传了字符串映射错误（"11" 自动 → NONE）
- 另一个坑：**strategy 属性** = 2（手动）时才能强制；若 APP 没写 strategy 而只调 setForceUse，`getOutputDevices` 读策略仍按自动算

### Q5：重启后用户选择丢失

- persist 属性被清：整机 factory reset 正常，非预期则查 `/data/property` 是否损坏
- APM 加载时序：`Aml_loadApmEngineLibraryAndCreateEngine` 在属性未就绪时读到默认值 0（自动）→ 需要在 `vendor/audio` 启动后属性已写入再初始化；确认 droidaudio 服务的 `init()` 时机
- 排查：重启后立即 `getprop`，看属性在哪个阶段恢复

### Q6：蓝牙 A2DP 播放断断续续 / 无声

- 看 `AudioDeviceBroker` 蓝牙连接日志 + `dumpsys audio | grep -i bt`
- engine 选择日志确认 A2DP 被选中；HAL 层 `audio_bt_hw.cpp` 的 codec 协商
- 音量：蓝牙走 AVRCP 音量，与本地曲线独立，检查 `BluetoothVolumeControl`

### Q7：改代码后编译/运行异常

- AIDL 修改后未清理中间产物 → Binder 代理方法空指针/TransactionTooLarge。**改 aidl 必须清理 out 下生成文件**
- 只改了 HAL 没重编内核模块 → HAL 与内核接口不匹配（混用旧模块）
- droidaudio 服务签名（sepolicy）未加 → 启动失败，`logcat | grep droidaudio` 查 selinux 拒绝，sepolicy 在 `device/amlogic/common/sepolicy/`

### Q8：audioserver 崩溃 / 音频服务反复重启

```bash
adb logcat -b crash | grep -i audio      # 查 crash 栈
adb shell dumpsys audio | head            # 查服务状态
```
- 常见：HAL 返回异常值、patch 越界（`AUDIO_PATCH_PORTS_MAX`）、空指针（设备列表空时 `getOutputDevices()[0]` 越界——**DisplayService.getCurAudioDevice 中 `outputDevice[0]` 在无 sink 设备时会崩**，注意防御）
- APM 死锁：`dumpsys media.audio_policy` 挂起时看 `AudioPolicyService may be deadlocked` 日志

### Q9：透传（RAW）无声或格式不对

- 确认源格式是否在 HAL 支持列表（`audio_hw_ms12_v2.c` 的 passthrough format 表）
- 内核 `iec_info.c` 是否识别到正确格式
- HDMI 透传还要看 TV 端 EDID 是否支持该格式（`dumpsys audio | grep -i edid`）

### Q10：音量跳变 / 切设备后音量不对

- 不同设备不同音量曲线（`AmlAudioPolicyManager::checkAndSetVolume` 定制过）
- 切换后 `applyStreamVolumes` 按新设备重算音量，跳变可查曲线表
- 排查：`dumpsys audio | grep -A20 "Volume"` 看各设备索引
